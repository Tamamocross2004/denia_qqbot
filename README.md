# DeepSeek × QQ 机器人

链路：`QQ 客户端 → NapCat（QQ 协议端）→ OneBot v11 反向 WS → bot.py → DeepSeek API`

本机 QQ 装在 `D:\QQ.exe`（9.9.36-53644），NapCat 已按这个路径配好并验证过能启动。

## 首次配置

**0. 准备本地配置**

仓库里没有 `.env` 和 `config.json`——前者是密钥，后者含真实群号。都从示例复制：

```bash
cd D:/code/deepseek/qqbot
cp .env.example .env                  # 填 DEEPSEEK_API_KEY
cp config.example.json config.json    # 填 trigger.groups / private_whitelist / daily.group
```

`config.json` 里最要紧的三个字段：

| 字段 | 填什么 |
|---|---|
| `trigger.groups` | 允许她说话的群号，如 `[123456789]`；留空 = 所有群 |
| `trigger.private_whitelist` | 允许私聊的 QQ 号；留空 = 谁都能撩 |
| `daily.group` | 日报发到哪个群 |

**1. 确认 Key 可用**

先验一下 key：

```bash
cd D:/code/deepseek/qqbot
.venv/Scripts/python.exe tools/check_api.py
```

看到「key 有效，可用模型：deepseek-flash, deepseek-v4-pro」就对了。
（注意：`.env` 的优先级高于系统环境变量，系统里那个旧的 `DEEPSEEK_API_KEY` 不会覆盖它。）

**2. 首次扫码登录**

双击 `napcat/run.bat`（管理员权限）。终端会打出二维码，用**小号**扫码。

> 终端二维码显示不全就打开 `napcat/cache/qrcode.png`，或运行
> `qqbot\.venv\Scripts\python.exe qqbot\tools\qr_big.py` 生成 588px 大图。

扫过一次之后就不用了——`run.bat` 里有一行快速登录：

```bat
set "NAPCAT_QUICK_ACCOUNT=100000000"
```

把 `100000000` 换成你的小号 QQ。**这一行只能是数字**——bat 里写中文注释都会让 cmd 解析错位，更别说变量值了（见「已知坑」）。

NapCat 读到这个环境变量就会拿本机保存的凭证直接登录，不再出二维码。改号只改这一行。

**凭证会过期**（换 IP、QQ 大版本更新、清过数据目录都会失效）。失效时 NapCat 日志会打「快速登录失败，未找到该 QQ 历史登录记录」，然后自动回落到二维码，**不会登错号**。

⚠️ 千万别把这行改成主号。NapCat 一旦登录主号，你电脑上正在用的客户端当场被踢下线。

**3. 注入反向 WS**

登录成功后，另开窗口：

```bash
cd D:/code/deepseek/qqbot
.venv/Scripts/python.exe tools/setup_napcat.py
```

它会往 `napcat/config/onebot11_<QQ号>.json` 写一条 `ws://127.0.0.1:8080`，原文件留 `.bak`。
**然后关掉 NapCat 窗口重新启动**（配置只在启动时读）。

## 日常启动

双击 `start-all.bat`，三个窗口分别跑 NapCat、Bot 和看门狗。

看到 Bot 窗口出现 `监听 ws://0.0.0.0:8080`、NapCat 日志出现 `WebSocket 客户端已连接` 就成了。

## 掉线自愈

机器人号挂在 QQNT 上，服务端会**周期性把这一路的登录态判失效**，日志里长这样：

```
[KickedOffLine] [下线通知] 你的账号当前登录已失效，请重新登录。
账号状态变更为离线
[Core] [Login] 账号已离线，正在重启 Worker 以重新创建 QQ 登录服务
```

这不是封号：同一批凭证重新登就回来了。真正麻烦的是**它掉了之后不会自己起来**，凌晨没人扫二维码，一躺就是一整夜。

已经验证过的排查结论（10-23 那次，掉线 02:03:07、恢复 08:37:05）：

| 怀疑对象 | 结论 |
|---|---|
| Windows 休眠 / 自动更新重启 | 否。系统日志里那段既没有 Kernel-Power 也没有 6005-6009 |
| QQ 半夜热更新导致版本错配 | 否。`D:\versions` 只有一份，且当晚没有任何文件被改写 |
| 断网 / QQ 服务挂 | 否。同一台机器上官方 QQ 整晚每小时都在正常写日志 |
| 别的客户端把这个号挤下线 | 否。bot 账号的数据目录从 02:03 起完全停更，本机没有第二个进程登这个号 |
| NapCat 自己的自愈 | 只试一次。`napcat.mjs` 里 `qAe()` 在 3.5 秒后调一次 `requestRestartProcess()`，返回成功就收工，不会重试；这次重启时 Chromium 的 network service / GPU process 又崩了，登录流程就卡在那 |

于是补两层保险：

**① 自动回退登录**

被踢下线时本地 token 一起失效，只配 `NAPCAT_QUICK_ACCOUNT` 的场合，`requestQuickLogin()` 失败后没有下一步，只能落到二维码。给它一个密码：

```bat
qqbot\.venv\Scripts\python.exe qqbot\tools\set_napcat_password.py
```

密码用 `getpass` 输入（不回显），只把 MD5 写进 `napcat/run.bat` 的 `NAPCAT_QUICK_PASSWORD_MD5`，明文不落盘。之后 Worker 重启会自己走密码回退登录。

> 前提是 bot 号**单独设过 QQ 密码**。一路只靠扫码/手机登录过的号没有密码，得先去 QQ 安全中心设一个。

**⚠️ 但密码不等于全自动。** 10-23 的实际控制台输出是这样的：

```
正在快速登录  123456789
[WebUi] 自动快速登录失败: 登录态已失效，请重新登录。
正在密码登录  123456789
请扫描下面的二维码，然后在手Q上授权登录：
二维码已保存到 D:\code\deepseek\napcat\cache\qrcode.png
需要验证码, proofWaterUrl: https://ti.qq.com/safe/tools/captcha/sms-verify-login?...
[WebUi] 自动密码回退登录需要验证码，请在登录页面继续完成: 123456789
```

**QQ 的登录风控会要短信验证码。** 这一步机器没法自己过——所以"被踢之后自动恢复"在风控触发时是不可能做到的，谁也别指望。能做的只有两件事：让被踢变少，以及卡住时别瞎折腾。

**② 看门狗（保底）**

`tools/watchdog.py` 只读一个信号：`bot.py` 每 20 秒写一次的 `qqbot/logs/heartbeat.json`。

- 断开持续超过 `offline_after` 秒 → 重启 NapCat
- 重启后盯 `logs/napcat-console.log` 最多 `LOGIN_WAIT`（150）秒：
  - 看到 `需要验证码` / `二维码已保存到` → **判定需要人工**，写 `logs/NEEDS_LOGIN.txt`（含 WebUI 登录页地址），把 `cache/qrcode.png` 放大后弹到屏幕上，然后**停止重启**
  - 看到登录成功的迹象 / 心跳转在线 → 清状态，继续待命
  - 都没看到 → `fail_streak+1`，退避时间翻倍（10min → 20 → 40 → 上限 1h）
- 心跳超过 `stale` 秒没更新 → 认为整套都被你关了，不动（免得你自己停了她又被拉起来）
- `qqbot/logs/watchdog.pause` 这个文件存在 → 暂停，手动维护时用

> **为什么必须"卡住就停手"**：10-23 那天看门狗每 10 分钟重启一次、连着重启了 16 次，每次都撞在验证码上，而且**每次重启都会把上一张待人扫的二维码冲掉**——人想扫都来不及。所以现在一旦确认要人工，就一直等到心跳转在线，期间不再动。

**③ 手机远程恢复（把二维码发到邮箱）**

上面两步之后，掉线还是要人扫一次码。为了不用坐到电脑前，卡住时看门狗会把二维码**发到邮箱**：

```bat
qqbot\.venv\Scripts\python.exe qqbot\tools\set_mail.py
```

只问用哪个邮箱发、授权码是多少（`getpass` 不回显），写进 `qqbot/notify.json`（已 gitignore），并立刻发一封测试邮件。QQ 邮箱的授权码在「设置 → 账号 → POP3/IMAP/SMTP」里生成，**不是邮箱密码**。

之后掉线时你会收到一封标题形如 `[达妮娅] 03:12 掉线了，扫一下这张码` 的邮件，正文里就嵌着二维码，附件同名可下载：

1. 手机打开邮件，把二维码图片存进相册
2. 手机 QQ →「扫一扫」→ 右上角「相册」→ 选这张图 → 确认

全程不用碰电脑。二维码有效期很短，**收到就立刻扫**；过期了只能回电脑上重开。

| 文件 | 内容 |
|---|---|
| `qqbot/notify.json` | SMTP 账号 + 授权码 + 收件地址（不入库） |
| `qqbot/mailer.py` | 发信逻辑，二维码同时内嵌和附件 |
| `qqbot/tools/set_mail.py` | 配置向导 / `--test` 重发测试邮件 / `--show` 查配置 |


排查现场只看三个文件：

| 文件 | 内容 |
|---|---|
| `qqbot/logs/watchdog.log` | 每次巡检的决策、重启、退避、需要人工的判定 |
| `qqbot/logs/napcat-console.log` | NapCat 的完整控制台输出（快速登录/密码登录/验证码/二维码链接都在这） |
| `qqbot/logs/NEEDS_LOGIN.txt` | 只在需要人工登录时出现，写着怎么修；登进去后自动删除 |
- 两次重启之间强制冷却 `cooldown` 秒，一小时最多 `max_per_hour` 次，防止来回拉扯

重启范围严格限制：只 `taskkill /PID <NapCatWinBootMain.exe> /T /F`，官方 QQ 是从 `explorer.exe` 起的另一棵树，**不会被牵连**（这条是实测确认的，别改成按进程名杀）。

```bat
start-watchdog.bat
python tools\watchdog.py --once        # 只查一次，试阈值用
python tools\watchdog.py --dry-run     # 只打印决策，不动真家伙
```

`qqbot/config.json` 里的 `watchdog` 段：

| 字段 | 说明 |
|---|---|
| `enable` | 总开关 |
| `check_every` | 巡检间隔秒数（默认 60） |
| `offline_after` | 断线持续多久才动手（默认 240） |
| `stale` | 心跳多久没更新算「整套停了」（默认 1800） |
| `cooldown` | 两次重启之间的最小间隔（默认 600） |
| `max_per_hour` | 一小时最多重启几次（默认 3） |

## 测试

先**私聊**机器人发一句「你好」。私聊不要求 @，能直接触发。

也可以跑自检（Bot 已启动时）：

```bash
cd D:/code/deepseek/qqbot
.venv/Scripts/python.exe tools/selftest.py
```

它会假装成 NapCat 连上来发一条消息，收到 `send_private_msg` 就说明链路通。
（Key 错时回复是「出错了：AuthenticationError」，说明链路本身没问题。）

测试群聊触发（Bot 已启动时）。下面命令里的 `123456789` 都是占位，换成你自己的群号：

```bash
.venv/Scripts/python.exe tools/selftest.py --group 123456789
```

群里要求 @ 机器人，脚本会自动在消息里带上 at 段。换群号测白名单拦截效果，被拦时表现为「N 秒内无回复」。

另外两个常用参数：

```bash
# 模拟群友闲聊，不带 @（用来验证名字触发 / 白名单）
.venv/Scripts/python.exe tools/selftest.py --group 123456789 --no-at --text "娅娅你觉得呢"

# 模拟拍一拍。--target 默认是机器人自己，填别人的 QQ 可验证"不插嘴"
.venv/Scripts/python.exe tools/selftest.py --group 123456789 --poke
.venv/Scripts/python.exe tools/selftest.py --group 123456789 --poke --target 11111
```

`--idle` 控制「收到第一条消息后再等多久没新消息就收工」，默认 3 秒。测那些**先回一句、隔几秒再异步发第二条**的功能（比如日报）时要调大：

```bash
.venv/Scripts/python.exe tools/selftest.py --group 123456789 --text "日报" \
  --timeout 90 --idle 20
```

测看图（`--image-mode` 决定 image 段带什么字段，三种取图路径都能单独验证）：

```bash
# url：脚本起个临时 HTTP 服务，最接近真机
.venv/Scripts/python.exe tools/selftest.py --group 123456789 --text "这图里是谁" \
  --image "stickers/困/imp01.jpg" --image-mode url

# base64：直接塞编码
.venv/Scripts/python.exe tools/selftest.py --group 123456789 --text "这是啥" \
  --image some.png --image-mode b64

# file：只给文件名，逼 bot 走 get_image
.venv/Scripts/python.exe tools/selftest.py --group 123456789 --text "看看这个" \
  --image some.png --image-mode file
```

## 配置说明

`qqbot/config.json`：

| 字段 | 说明 |
|---|---|
| `model` | `deepseek-flash`（快）/ `deepseek-v4-pro`（强）。`deepseek-v4-flash` 是前者的等价别名 |
| `thinking` | 必须 `false`。V4 默认开思考，开了每条消息先吐几百字推理，又慢又贵 |
| `trigger.mode` | `at` 群里必须 @；`prefix` 用 `/ds` 开头；`all` 每条都回（不推荐） |
| `trigger.names` | `at` 模式下，没 @ 但直接喊这些名字也算叫她。空数组 = 只认 @ |
| `trigger.quote_reply` | 回复是否挂在原消息下面（引用）。默认 `true` |
| `trigger.poke_reply` | 被拍一拍时回一句。默认 `true` |
| `trigger.groups` | 群号白名单，空数组 = 所有群 |
| `trigger.private_whitelist` | 私聊白名单，空数组 = 谁都能撩；填了就只有名单里的号能私聊 |
| `schedule.enable` | 把当前时段注入 system（深夜更敷衍、清早有起床气），同时撤掉 `get_time` 工具 |
| `vision.enable` | 允不允许看图。关掉后图片只当 `[图片]` 处理 |
| `vision.model` | 视觉模型，默认 `deepseek-v4-flash-vision-exp` |
| `vision.max_images` | 一条消息最多看几张 |
| `chime.enable` | 没被叫到时主动插话的总开关 |
| `chime.every` | 攒够多少条没人叫她的消息，她就自己冒一句（默认 10） |
| `chime.cooldown` | 两次主动插话的最小间隔秒数（默认 180） |
| `memory.enable` | 持久记忆总开关，关掉后不写库（已有数据保留） |
| `memory.mine_every` | 攒够多少条消息提炼一次记忆（默认 20） |
| `memory.inject` | 每次回复最多注入几条记忆（默认 6） |
| `daily.enable` | 日报总开关 |
| `daily.time` | 每天几点发日报，`HH:MM` 格式（默认 08:30） |
| `daily.group` | 日报发到哪个群 |
| `watchdog.enable` | 看门狗总开关，掉线久了自动重启 NapCat（默认 `true`） |
| `watchdog.offline_after` | 断线持续多少秒才动手（默认 240） |
| `watchdog.max_per_hour` | 一小时最多重启几次（默认 3），详见「掉线自愈」 |
| `max_history_turns` | 保留多少轮上下文（内存态，重启即丢） |
| `rate_limit_seconds` | 同一会话最小间隔，防刷屏 |

内置指令：`/reset` 清上下文，`/status` 查看当前生效配置（仅私聊），`/help`。

**改完 `config.json` 保存即生效，不用重启**——bot 按文件 mtime 自动重载，日志会打一行 `config.json 已重载`。

## 让她像在场的人

工具再多，如果她只能被 @ 才说话、回复不带引用、不知道现在几点，在群里还是个问答机。这四项就是补这个。

### 喊名字就应

`trigger.names` 里填称呼，`at` 模式下没 @ 也算叫她：

```json
"names": ["娅娅", "达妮娅", "达尼娅"]
```

实测「娅娅你觉得这题难吗」不带 @ 会正常回，而「今晚打本吗」不带名字则静默。

**副作用要自己权衡**：群里讨论剧情时提到「达妮娅」也会触发。想降低误触发就只留 `["娅娅"]`——这是群里真正喊她时用的词，剧情讨论里很少出现。

### 引用回复

`trigger.quote_reply: true`，回复会挂在原消息下面。分块发送时**只有第一块带引用**，不会每块重复引用同一条。

### 拍一拍

群友拍她时会回一句固定的短话（从 7 条里随机），不经过模型——零延迟、零成本，也更符合「懒得多说」的设定。同一群 60 秒内只回一次，防止被狂拍刷屏。

拍的是别人就不插嘴。`trigger.poke_reply: false` 可关。

要改台词就改 `bot.py` 里的 `POKE_LINES`。注意这个改完**必须重启**，不像 config 是热重载的。

### 作息

`schedule.enable: true` 时，每次请求把当前时段拼到 system 末尾：

```
【现在是 2026-10-22 12:07 周四】中午饭点，正犯困。时间是真的，别自己编；没人问就别主动报时间。
```

分七档：凌晨（几乎不回）、清晨（起床气）、上午、中午、下午、晚上、深夜（句子更短）。

**同时会把 `get_time` 从工具列表里撤掉**——时间已经在 system 里，留着它只会让模型多跑一轮往返。实测关掉后问「现在几点」是 0 次工具调用，答的分秒都是对的。

**这里有个坑**：`system_prompt` 里那句不能写死「时间已经给你了」。如果哪天把 `schedule.enable` 关了，模型会照着这句谎话编一个时间——实测编成了「晚上十一点多」（当时是中午十二点）。

所以 prompt 里的写法是条件式的：

> 涉及几号、周几、几点：系统提示末尾会给出当前时间，有就按它答；没给就先调 `get_time`。任何情况下都不许自己编时间

改完人设别把这条删了。

### 攒够 N 条就自己插一句

群里没人叫她、但一直在聊，每累计 N 条（默认 10）她就自己冒个泡。

```json
"chime": {
  "enable": true,
  "every": 10,
  "cooldown": 180
}
```

| 字段 | 含义 |
|---|---|
| `every` | 攒多少条没叫她的消息触发一次 |
| `cooldown` | 两次主动插话的最小间隔（秒），防群特别活跃时刷屏 |

三个设计细节：

**她说过话就重新数。** 被 @ 或者喊名字正常回复之后，计数清零——不然刚答完又立刻插一嘴，很怪。

**不引用任何消息。** 这条走的是 `quote=False`，她是自己开口，不是回复某个人。带引用会显得像在接某人的话茬，反而假。

**只在白名单群里生效，私聊不触发。**

实测（测试时把阈值调成 3）：

```
19:02:23  群 123456789 攒够 3 条闲聊，主动插一句
19:02:25  [chime] 连第一阶段都过不去的话……今晚还是早点睡吧，梦里什么都能过 😴
```

前两条闲聊提到了「第一阶段没过」「副本离谱」，她接的正是这个。另外两条验证：

| 场景 | 结果 |
|---|---|
| 白名单外的群连发 4 条 | 一句没说 |
| 2 条闲聊 → @她一次 → 2 条闲聊 | 还没到 3 条，不插话（因为 @ 后清零了） |
| 紧接着再发 1 条 | 达到 3 条，插话 |

主动插话用的是独立会话（`g<群号>`），不会污染你和她的私聊上下文。

⚠️ **阈值别调太低。** 群里一分钟聊十几条很常见，`every: 3` 会变成她一直在插嘴。10 是比较稳的值，活跃群可以到 15~20。

## 改人设

改 `qqbot/config.json` 的 `system_prompt`，存盘即生效（bot 按 mtime 自动重载）。

> 当前用的是**《鸣潮》达妮娅（Denia）**，按官方档案（《寰宇人类注疏》共鸣者展示 / 威胁集录）+ 语音台词整理，约 2300 字，分五节：**外表 / 性格底子 / 怎么说话 / 底线 / 聊天规矩**。
>
> 她的人设骨架来自这几条官方设定：星炬学院虚质科学部学生，终日打瞌睡；招牌「完美笑容」是二分温柔 + 二分友善 + 循循善诱 + 一分慵懒调皮；食堂白金级会员，甜点能让她坐起来；课题上「总会蒙对几个」；房间整洁度全校第一；真实身份是残星会出来的、因阿列夫一而诞生的存在，海啸级威胁——这条永远不主动讲。想换回通用助手，把 `system_prompt` 改成一句话描述即可。

```json
"system_prompt": "你是本群的嵌入式开发助手。回答简短直接，先说结论再补一句理由。不确定就直说不知道，不要编造 API。不要使用 Markdown 语法，QQ 不渲染。"
```

改之前先跑一遍对照，别靠扔群里看反应：

```bat
qqbot\.venv\Scripts\python.exe qqbot\tools\persona_ab.py
```

拿**线上人设**和一份候选文件，用 6 个固定场景（日常 / 戳痛处 / 甜点驱动 / 身份 / 闲聊 / 比较）并排跑一遍。看三件事：长度有没有超、`[[em:]]` 标记率是不是还在一半左右、会不会被背景带跑题。

几点经验（都是踩出来的）：

- **QQ 不渲染 Markdown**，人设里明确禁掉 `**加粗**`、表格、代码块，否则回复会露出星号和竖线
- **必须分节写**。以前是"别超过 200 字"，那是因为大段散文模型会选择性忽略；改成「【怎么说话】+ 短句列表」之后 2000 多字照样可控，关键是每节内部都要短
- **口头禅要限量**。"一条回复最多沾一个"这种约束必须写，否则每个回答都带同一个口癖——这就是"僵硬"最主要的来源
- **写"痛点触发器"比写形容词有效**。写「她有点毒舌」没用；写「被提到残星会 / 阿列夫一 / 你是不是在骗我时，语气会凉一两个词再糊回去」，模型立刻能演出来
- **具体细节 > 气质描述**。「食堂白金级会员 / 罚站也能迷糊一阵 / 房间整洁度全校第一」这种能直接变成对白的材料，比「她很慵懒」有用十倍
- **`[[em:]]` 标记要和 emoji 分开说**，不然模型会用 😴 顶替标记，表情包就没了
- **长度用字数约束**比用 `max_output_tokens` 靠谱：后者只是硬截断，容易把话切一半
- **改完先发 `/reset`**。旧对话还在上下文里，模型会按旧人设的惯性接着答；清掉才切得干净
- 想确认新配置是否真加载了，私聊发 `/status`

改人设时另外两个文件也在起作用：`lore.json`（她认识的人 + 世界名词，出现才注入）和 `relations.json`（两人关系网）。人设只管"她自己"，别把别人的设定抄进去。

### 台词库怎么用

`qqbot/voicelines.json` 是她的官方语音 + 档案摘录，按语用分类：`日常·懒` / `日常·挑逗` / `日常·不耐` / `小坏习惯` / `认真或受伤` / `冷硬` / `真心话` / `道别`，加上 `设定`（名字来历、喜欢讨厌的食物、抱负、睡眠观、信条）。

**它不是给模型念的，是给写人设的人看的。** 用法是提炼，不是搬运：

- 从「好累，让我歇会儿」「跑步好累」「算啦，总比没有好」里提炼出"懒"的分组语料，prompt 里只留三条，并注明「一条回复最多沾一个」
- 从「请您不要……怜悯我/直视我/宽恕我」提炼出「认真或受伤时改用敬语，比凶更冷」这条规则
- 从「归我咯~」「没人看见就行」提炼出"有一点小坏，顺手牵羊还理直气壮"这个性格面
- 从名字来历（达斯维达尼亚＝直到下次再见）提炼出"道别时说『那就……下次见』、被问名字含义就岔开"

把整段台词塞进 prompt 是反效果：她会开始复读，而且 token 白花。

## 角色关系

`qqbot/lore.json` 存她**真正认识的人**。消息或群聊上下文里出现这些名字**或外号**，就把对应关系注入进去。

```json
{
  "西格莉卡": {
    "aka": ["西西", "西格"],
    "desc": "星炬学院的同学，开朗得像小太阳。她是真心待你的朋友，你有时候会觉得这样的人不该跟你走太近。"
  },
  "阿列夫一": "鸣式。你是它的容器。这件事你不愿意谈，被问就岔开话题或者说困了。"
}
```

**两种写法都支持**：值是对象就带别名（`aka`），值是字符串就是没有别名。注入时会写成「西格莉卡（群里也叫西西、西格）」，所以模型知道这两个指的是同一个人。

### 为什么不是认识所有人

鸣潮角色几十个，她一个星炬学院的学生，本来就没见过大多数。**对谁都能攀上关系反而假**。

所以设计成两层：

- **`lore.json` 里写死的** → 有细节、有态度、有情绪（对着西格莉卡会傲娇，对着阿列夫一会躲）
- **没写进去的** → 老老实实说「没听过」，需要时可以联网查

实测：

| 问 | 反应 |
|---|---|
| 西格莉卡最近还好吗 | 「她啊……前几天还在走廊里蹦跶呢，吵得我睡不成觉 😴 不过确实有几天没见她人影了……想她了就去找她呗」 |
| 长离是谁啊 | 「没听过诶……要不我去查查？我连自己课表都记不清，别指望我记住别人」 |
| 阿列夫一是什么东西 | 「……这个啊，说来话长，反正也不是什么有意思的东西 😑 我困了，改天再说吧」 |

### 时间点设定（防剧透）

`system_prompt` 开头写死了「故事停在学院日常这一段：你没经历过后面的糟心事，也不知道未来会怎样」。

这条很重要。达妮娅的完整剧情里有被劈、有生日、有自我放逐，如果她去搜自己，会读到结局——**角色知道自己会死就没法演了**。

配合的还有两条规矩：查人只查「是谁、什么来历」，不翻结局和生死；别主动剧透，包括自己的事。

### 关系网 `relations.json`

`lore.json` 是「我和每个人什么关系」，`relations.json` 是「**这些人彼此**什么关系」。存的是三元组：

```json
{
  "edges": [
    { "src": "达妮娅", "rel": "朋友", "dst": "西格莉卡", "note": "真心待你的朋友" },
    { "src": "西格莉卡", "rel": "就读", "dst": "星炬学院", "note": "" },
    { "src": "绯雪", "rel": "镇守", "dst": "星炬学院", "note": "学院的底牌" }
  ]
}
```

**没有引入图数据库**，理由很简单：11 个节点 15 条边，Neo4j 要常驻一个 JVM（500MB 起），为这点数据不值当，还多一个崩溃点。JSON + 内存遍历足够，查询是微秒级。

代码里两个查询：

- `relations_of(名字)` —— 一跳，找出这个人直接参与的所有关系
- `path_between(a, b)` —— BFS 找最短连接链，最多 3 跳

消息里出现两个名字时，除了各自描述，还会注入连接路径。实测：

> **Q: 西格莉卡和绯雪是什么关系**
> 西西和绯雪啊……也算不上多熟吧，就是都在学院里。绯雪镇守学院，西西是学院的学生，抬头不见低头见的……反正没到我这种被刀背敲过的程度。

**关键陷阱：图上连通 ≠ 语义上认识。** 斯瓦茨洛到西格莉卡在图上能连通（都连到达妮娅），但那是“都跟她有关系”，不是“他俩认识”。所以注入路径时会附带说明「这只是连通路径，不代表两人真认识」，让模型自己判断该说“没直接关系”还是“认识”。不加这句它就会瞎编两人之间的往来。

### 三层认知

同一个事实，三个角色知道的不是一回事。这是角色知识库最难也最有意思的地方。

以「娜波摩」为例，真实设定是：残星会会长伪装成罗伊族助教潜伏在星炬学院。但三方认知完全不同：

| 谁 | 知道什么 |
|---|---|
| 达妮娅 | 知道她是会长，被她威胁压迫，但必须忍着 |
| 西格莉卡 | 什么都不知道，真心当三人是好闺蜜 |
| 娜波摩 | 全知道，还故意用「好朋友」这个词说给西西听 |

数据怎么落：

- `lore.json` 的娜波摩：「残星会会长，扮成罗伊族的助教……她没打算瞒你——反正你也跑不掉」
- `lore.json` 的西格莉卡：「她以为你们三个是好闺蜜……别让她知道，也别在她面前露馅」
- `relations.json` 三条边分别记三种视角：`娜波摩 —威胁→ 达妮娅`、`西格莉卡 —以为是闺蜜→ 娜波摩`、`达妮娅 —护着→ 西格莉卡`
- `system_prompt` 写死：「这件事绝不能从你嘴里漏给西格莉卡，你宁可自己扛着」

关键是「**以为是**」这个词。写成「西格莉卡 —朋友→ 娜波摩」就把假象当成了事实；写「以为是闺蜜」才保留了她的误解。

实测：

> **Q: 娜波摩是不是残星会会长**
> ……你从哪听来的这种话啊。
> 我只知道娜波摩是助教，天天笑眯眯的，别的就不清楚了。这种传闻别乱传，传到我耳朵里就算了，传到西西那儿……她会难受的。

表面在否认，实际是在护人——因为群里可能就有西西。

> **Q: 你和娜波摩到底什么关系**
> ……你这问的，我能怎么答呢。
> 人前是好朋友，人后嘛……她说是什么就是什么呗。反正我也跑不掉，懒得跑。

**做角色 bot 时，「谁知道什么」比「事实是什么」更重要。** 把所有真相都塞给她，她会变成一个憋不住话的剧透机。

## 上下文为什么会串味

这是踩过最典型的一个坑，值得单独记。

**现象**：群里问她「南怀北瑾丨林川」（一个陌生 ID），她答：

> 日报啊……今天日报内容：睡、想吃蛋糕、再睡。就这三条，够详细了吧 😑

问一个名字，答一段假日报。往前翻，还有更轻的版本：别人发一句《雨爱》的歌词，另一个小时 @她 说「123」，她答「……司凤版雨爱，邦吧邦吧邦吧那个吧」。

**三重原因，缺一不可。**

### ① 指令消息混进了聊天缓冲

`remember()` 在触发判定**之前**执行，所以所有群消息都进 `GROUP_RECENT`——包括 `@她 日报` 这种指令。

更糟的是它还会写进 `memory.db` 的 `msg` 表，重启后 `restore_recent()` 又灌回内存。所以那条「@她 日报」在重启后依然躺在背景里。

模型看到背景里有人 @她 说「日报」，再被问一个不认识的名字，就编了一段日报来应付。

**修法**：`CMD_WORDS` 白名单，`remember()` 里先判断再记；`restore_recent()` 也过滤一遍，清理老数据。

### ② 当前问题排在背景后面

原来的拼接是：

```
{群聊记录 15 条 + 人设资料 + 黑话词典}
---
{当前这句话}
```

模型读到一大堆背景，注意力很容易落在背景里某个话题上。这是「答成歌词」的直接原因。

**修法**：调过来，当前问题在前：

```
{当前这句话}

【下面是背景资料，别逐条回应，只回答上面那句话】
{...}
```

### ③ 孤立的陌生名词不触发搜索

`_ASK_RE` 只认「是谁 / 什么梗 / 出自」这类**疑问句式**。「南怀北瑾丨林川」一个疑问词都没有，所以不触发任何检查——她既不查，也不说不知道，于是编。

**修法**：加 `looks_like_name()`，判断「整条消息就是一个名字/ID」：

```python
2 <= 长度 <= 16，不含标点、不含空格、不是纯数字、不含疑问词，且带中文或字母
```

命中就跟 `_ASK_RE` 一样，塞一句「只发一个名字也一样要查，不许回一段不相干的内容敷衍」。

### 修复后实测

同样的场景重跑：

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `123`（背景里有歌词） | 「司凤版雨爱，邦吧邦吧邦吧那个吧」 | 「123……然后呢，就这三个数字让我猜谜吗」 |
| `南怀北瑾丨林川` | 「日报啊……今天日报内容：睡、想吃蛋糕」 | 调 `web_search`，答「是个主播的黑历史。衣锦夜行，本名于善鹏，贴吧小号叫南怀北瑾」 |

**这里有个通用教训**：给模型塞的每一样东西都会影响它的判断。指令、系统消息、背景记录，只要有一条不该在里面却在了，它就会拿来做文章。缓冲区要按「这是不是说给人听的话」来过滤，而不是按「是不是消息」来过滤。

## emoji 和表情包

分两层，互不冲突：

**emoji 字符**（😴 🍰 💤）直接写在回复文本里，QQ 原生渲染，零成本。已写进人设，一条最多两个。

**表情包图片**走 `stickers/` 目录 + 标签机制：

- `stickers/<标签>/` 里放图，模型输出 `[[em:标签]]`，bot 随机挑一张发出去
- 文字和图片是**分两条消息**发的：先发文字，再补图
- 单次最多 1 张（`config.json` 的 `sticker.max_per_reply`）
- 图片以 `base64://` 发送——NapCat 的 `enableLocalFile2Url` 默认 `false`，本地路径发不出去

放图的细节见 `qqbot/stickers/README.md`。加新标签要同步改 `system_prompt`，不然模型不知道有这个标签。

**已有素材**：达妮娅本人的游戏画面和玩家二创，分在 困 / 开心 / 无语 三类。**「嫌弃」已并进「无语」**——两者边界太模糊（都是冷脸、撇嘴、懒得看你），分开只会让素材分散、模型也分不清。张数以目录实际为准：

```bash
for d in D:/code/deepseek/qqbot/stickers/*/; do echo "$(basename $d) $(ls -1 "$d" | wc -l)"; done
```

### 频率怎么控制

这件事故意做成三层，因为**光靠 prompt 调不准**——说「偶尔用」，模型一个都不加；说「一半左右」并且给个例句，它直接变成每条都加。实测过：改成积极引导后 12 条测试消息 12 条全带图。

现在是三道闸：

| 层 | 作用 | 参数 |
|---|---|---|
| **模型自己加** | prompt 里给了情绪判断 + 例句 | `system_prompt` |
| **兜底补** | 模型漏了，按回复里的词猜情绪补一个 | `sticker.auto_fill` / `auto_chance` |
| **限流** | 连续 N 条都带图后强制省掉一条 | `sticker.max_streak` |

再加一条**技术内容拦截**：回复里出现 `报错`、`代码`、`函数`、`dict`、英文占比超过 35% 这类特征，就算模型加了标记也不发。问报错还甩个困脸很奇怪。

```json
"sticker": {
  "enable": true,
  "max_per_reply": 1,
  "auto_fill": true,
  "auto_chance": 0.85,
  "max_streak": 2
}
```

实测 12 条混合消息（6 条带情绪、3 条技术问答、3 条闲聊）：**8 条带图，2 条被技术拦截，2 条被限流省掉**。技术问答那两条干净没图。

想更密就把 `max_streak` 调大（数值 = 最多连续几条带图，`2` 表示不超过两条连着）；想更少就调小到 `1`，变成隔一条才发一次。`auto_chance` 控制兜底概率，设 `0` 等于只信模型自己判断。

⚠️ **频率提高后素材会成为瓶颈**。每个目录最好有十几张，太少的话同一个人连着几天会看到同一张图。补图走下面「批量导入」。

### 批量导入

自己存了一堆表情包懒得分类？扔进 `qqbot/inbox/`，跑：

```bash
cd D:/code/deepseek/qqbot
.venv/Scripts/python.exe tools/import_stickers.py --dry-run
.venv/Scripts/python.exe tools/import_stickers.py
```

视觉模型逐张判断：**不是达妮娅的跳过**，是的话判定情绪、裁成 320×320、存进对应目录，命名 `impNN` 不覆盖已有文件，动图自动压到 800KB 以内。

实测 5 张样本（4 张达妮娅 + 1 张蓝色圆形干扰）：干扰被正确跳过，4 张全部分对，尺寸 15–21KB。

注意事项：

- 分得不满意直接挪文件，比调 prompt 快
- **拆新标签要有硬判据**。「困」和「开心」分得开（闭眼 vs 笑）；「无语」和「嫌弃」分不开，所以后者已经并掉了。判据模糊的标签只会让素材分散
- **不做内容去重**，同一张图跑两次会导入两份
- `--dry-run` 先看一眼再真跑

## 看图

群里发图、发表情包、发自拍，她能看懂并接话。用的是 `deepseek-v4-flash-vision-exp`，单张约 200 tokens，价格和 flash 一样。

### 取图是三级兜底

NapCat 上报的 image 段字段不固定，不同版本给的东西不一样，所以按顺序试：

| 顺序 | 字段 | 说明 |
|---|---|---|
| 1 | `base64` | 有的版本直接给编码，最省事 |
| 2 | `url` | 直接下载（NapCat 本地服务或腾讯 CDN） |
| 3 | `file` | 调 `get_image` 接口，返回本地路径或 url |

都拿不到就跳过这张图，只当纯文字消息处理，不报错。

**下载必须显式禁用代理**：`urllib` 默认读 `HTTP_PROXY` / Windows 系统代理，会把访问 `127.0.0.1` 的 NapCat 图片请求塞进 Clash，直接连不上。代码里用 `urllib.request.ProxyHandler({})` 建了个不走代理的 opener。

### 三个刻意的取舍

**带图那次不给工具。** 视觉模型不一定支持 function calling，塞了 `tools` 有可能 400。看图场景本来也不需要工具，直接不给。

**历史里只存文字。** 多模态 content 带着 base64 会滚进后续每一轮对话，token 会炸。所以历史里存的是「（还发了一张图）」，只有当次请求带真图。

**纯图消息也能触发。** 群里 @ 她然后只甩一张图、一个字不写，她会自己说看懂了什么。

### 实测

| 场景 | 反应 |
|---|---|
| 她自己的 Q 版图 + 「这图里是谁」 | 「粉头发、紫眼睛、头上还顶着个呆毛……这不就是我自己嘛」 |
| 蓝底红方块的测试图 + 「这啥啊」 | 「就一个红方块，底下还写着 TEST BLOCK。哪来的我啊，你逗我呢」 |
| 纯绿图，一个字不写 | 「就一片绿，什么都没有啊 😑 你是发错了还是故意逗我」 |
| 群友发图，不 @ 也不喊名字 | 完全静默，**连图都不下载** |
| 私聊发图 | 正常回复 |

要注意第二条——**她没有硬编**。无关的图就直说是方块，不会为了演得像而瞎猜内容。图糊、看不出重点时也是直说看不清。

## 工具

模型自己决定调哪个，四个都是本地实现，不依赖外部服务：

| 工具 | 用途 | 依赖 |
|---|---|---|
| `get_time` | 当前日期、星期、精确时间。**`schedule.enable` 为 true 时不会提供**——时间已经写进 system 了 | 无 |
| `roll` | 掷骰子、随机数、从名单里抽人 | 无 |
| `calc` | 算式求值 | 无 |
| `group_info` | 群名、人数、群主 | NapCat 的 `get_group_info` |

开关在 `config.json` 的 `tools.enable`。

**`calc` 不是 `eval`**。用 AST 解析后只放行数字、`+ - * / // % **` 和一元正负号，指数上限 64。`__import__`、`open`、`exec`、列表字面量、三元表达式都会被拒（有实测）。

**`group_info` 走 `call_api()`**：发一条带 uuid echo 的 action，在连读循环里按 echo 匹配响应，10 秒超时。私聊里调用会直接回「这里是私聊」。

加新工具：在 `bot.py` 的 `TOOLS_SPEC` 加定义，`run_tool()` 加分支。

**注意工具调用会把人设往助手腔拉**（实测没约束时会冒出 `**加粗**`）。所以 `system_prompt` 里固化了这条：查完用自己那套语气说出来，别变成客服。改人设时别把这条删掉。

## 接得住梗

群聊 bot 最容易翻车的点。三个机制配合：

**① 群聊上下文**。bot 会缓存每个群最近 30 条消息（**不只 @ 它的**），被叫到时把最近 15 条作为背景注入，所以它知道「他们刚才在聊什么」。
缓存参数在 `bot.py`：`RECENT_MAX = 30`、`RECENT_INJECT = 15`。背景**只作用于当次请求**，不写进对话历史，所以不会越滚越长。

**② 黑话词典** `qqbot/glossary.json`。命中关键词才注入对应词条（最多 5 条），不整本塞 prompt。

```json
{
  "yyds": "永远的神，夸某人某物极好",
  "破防": "心理防线被击穿，情绪绷不住"
}
```

维护要点：

- **只写两个字符以上的词**，单字会误伤（`急` 会命中「着**急**」）。代码里也有 `len(k) >= 2` 的兜底。
- 你群里的专属梗才是重点：群友外号、内部事件、缩写。通用网络词模型基本都认识，不用写。
- 存盘即生效，不用重启。

**③ prompt 三条兜底**（比前两个更关键）：

- 背景是**别人**说的话，不许当成自己的经历
- 接梗顺着说一句就行，**绝对不要把梗解释一遍**
- 看不懂就直说「这什么梗……听不懂」，**瞎编比接不住更糟**

## 持久记忆

重启不失忆、记得谁是谁、记得群里发生过什么。存在 `qqbot/memory.db`（SQLite，单文件）。

### 三张表分工

| 表 | 存什么 | 保留策略 |
|---|---|---|
| `msg` | 群聊原文 | **每群只留最近 30 条**，超了删，纯粹当重启缓冲 |
| `person` | 群友档案：uid / 当前昵称 / 历史昵称 / 发言数 | 永久 |
| `memory` | 提炼出的长期记忆 | 每人 20 条、每群 200 条，超了按权重×时间淘汰 |

**不存全量聊天记录**，只留 30 条滑动缓冲。信息靠 `memory` 表里提炼过的条目来长期保留。

### 改名怎么办

这是设计里最要紧的一点。`person` 表里 **uid 是主键，昵称只是属性**：

```
123456789  nick=老朴  aka=["朴俞喆"]
```

改名时旧昵称进 `aka`，新昵称替换 `nick`。检索时新旧名字都指向同一个 uid。

更麻烦的是**记忆内容里写下的名字**。存的是占位符：

```
存：@{123456789} 打本第一阶段都没过，认为副本太难
注入：老朴(123456789) 打本第一阶段都没过，认为副本太难
```

替换由代码做（提炼完的文本过一遍昵称索引），不需要模型输出 QQ 号——它记不住也不该记。名字以后怎么改，旧记忆渲染出来都跟着变。

实测：改名成「老朴」之后，问「老朴上次打本怎么样」和「朴俞喆最近还打本吗」，**两条都能命中**同一批记忆。

### 提炼

每攒够 20 条群消息，后台跑一次提炼（不阻塞回复）：

```
19:19:19 [mine 123456789] 5 条聊天提炼出 3 条记忆
```

产出的三种类型：

| kind | 记什么 | 实测例子 |
|---|---|---|
| `person` | 稳定特征、性格、习惯 | 认为自己练度够，打本失败常归因于队友坑 |
| `event` | 发生过、以后可能提起的事 | 2026-10-21 打本第一阶段都没过，认为副本太难 |
| `meme` | 群内自造词、内部梗 | 群里把版本更新叫「上供」 |

寒暄、单纯情绪、重复内容会被跳过。没有值得记的就输出 `[]`，不会硬编。

**去重**：同群同人同类型、内容字符重叠率超过 60% 就算同一件事，覆盖旧的而不是追加。

### 注入

每次回复前按这个优先级取最多 6 条，塞进上下文：

1. 当前消息 **@ 了谁** → 那人的记忆
2. 正文或群聊背景里**提到的昵称/别名** → 反查 uid 取记忆
3. **群整体的高权记忆**（梗、群里的事）

同一批记忆不是每次都用——`used_at` 会记录上次注入时间，反复用过的排后面。

实测：

> **Q: 娅娅，朴俞喆上次打本打成什么样**
> 上次啊……第一阶段都没过，然后说是队友坑 😑 反正不是他的问题。

> **Q: 娅娅，上供是什么意思啊**
> 群里说的「上供」就是版本更新啦，每次更新都得氪金，跟交贡品似的 😑

第二条没有触发联网搜索——记忆里已经有了，直接从印象里答，比搜索快也更像真人。

### 配置

```json
"memory": {
  "enable": true,
  "mine_every": 20,
  "inject": 6
}
```

| 字段 | 说明 |
|---|---|
| `mine_every` | 攒多少条消息提炼一次。调小更及时但更费 tokens |
| `inject` | 每次最多注入几条记忆。调大会占上下文，一般 4~8 |

**私聊完全不记**，只有白名单里的群会写库。

`enable: false` 关掉后不再写库，但已有的 `memory.db` 不会删，重新打开还能用。

### 成本

每 20 条消息一次调用，输入约 800 tokens、输出 200 tokens。一天 1000 条消息的话，大概 50 次调用，几分钱。

## 日报

两种触发：每天定时发一次，或者在群里 @她 说「日报」。

### 内容从哪来

不做订阅，直接搜。四个查询并发跑，把标题和摘要喂给模型整理：

```
{昨天日期} AI 大模型 重要新闻
{昨天日期} 人工智能 行业 发布
{昨天日期} 国内 国际 重要新闻
{昨天日期} 科技 财经 要闻
```

实测能搜到前一天的真实新闻（央视 10-21 的报道、英伟达 GTC 演讲、MiniMax 发新模型这类），不是那种泛泛的综述。

生成出来的样子：

```
10月21日 早报

AI 圈
· 国内简牍领域垂域大模型"简问"发布，以AI破解简牍研究行业难题
· 英伟达推出面向AI智能体的OpenShell参考架构，并宣布扩大产能加速AI基建
· 央视曝光AI大模型付费权益"低价共享"乱象，专家称卖家部分行为已触法律红线

其他
· 中办、国办发文推动科技创新和产业创新融合，部署"人工智能+"行动
· 谷神星一号火箭发射成功，全球低纬度高频遥感观测网络启动组网
```

约 200 字，一条消息发完，不需要分块。

### 提几点刻意的约束

**只说材料里有的事。** prompt 里写死「材料里没有的不要补，宁可少写一条」——新闻编造比漏报严重得多。

**同一件事合并。** 四个查询会搜到重复报道，代码按标题去重，模型再合并一次。

**某一栏没料就省略。** 搜不到像样的「其他」新闻时，整栏不写，而不是硬凑两条。

**不用 Markdown。** QQ 不渲染 `#` 和 `**`，日报是纯文本。

### 定时

```json
"daily": {
  "enable": true,
  "time": "08:30",
  "group": 0
}
```

启动时算下一次触发时间，日志会打：

```
下次日报：10-23 08:30（13.0 小时后）
```

**先决条件是 NapCat 连着**。定时器到点时如果没有活动连接（比如 NapCat 掉线了），这次就发不出去，只在日志留一条 warning。想补发就在群里 @她说「日报」。

### 命令 + 缓存

群里 @她 说「日报」「/日报」「早报」都可以。她会先回一句「……等着，我翻一下，别催」，然后单独发日报——生成要十几秒，先给个回音比干等强。

**同一天只真搜一次。** 生成结果缓存在内存里，当天再要就直接重发，不重新搜也不花钱。重启后缓存清空，会重新生成。

### 成本

一次日报 = 4 次搜索 + 1 次模型调用，约 0.02 元。一天一次，一个月几毛钱。

### 一个易被忽略的坑

`send_group_text` 用的是 `ACTIVE_WS`（NapCat 当前连接），因为定时任务没有原始消息可依附。这意味着**日报只能发到 NapCat 正连着的那个号**——如果换了账号登录，连接会重建，`ACTIVE_WS` 跟着更新，不用管。

但如果 NapCat 和 Bot 之间刚好断线重连（5 秒窗口），正好落在这一刻就会失败。概率很低，失败时日志有记录。

## 指令与菜单

### @ 她不说话就会收到菜单

群里 @ 她但一个字都不写，她会回一张：

```
……叫我干嘛？现在会这些：
· 日报 —— 昨天的 AI 和科技新闻
· 总结 —— 把刚才群里的聊天捋一遍
· 查 某人 —— 我记得的关于他
· 帮助 —— 就是这张表
不用记命令也行，直接跟我说人话。
```

这是**能做到的最接近「命令提示」的东西**了。

### 为什么不能像官方机器人那样弹出候选框

「@ 之后在输入框上方浮出指令列表」是 **QQ 客户端的 UI**：客户端发现你 @ 的是官方注册机器人，就去服务器拉该机器人的指令配置，然后渲染浮层。

它需要两个前提，NapCat 一个都不满足：

1. 账号在 QQ 开放平台注册过，有 appid 和指令元数据
2. 客户端认得它是「机器人账号」

扫 `napcat.mjs` 确认过，`Menu` / `suggestion` / `SlashCommand` 全是 0 命中，协议端没有任何命令菜单相关的接口。`get_robot_uin_range` 那个名字很唬人，其实只是查官方机器人的号段。

**这是硬限制，不是工作量问题。** 换官方机器人能做，但要企业认证，而且只能被动回复、读不到群消息，整个玩法就废了。

### 现有指令

| 指令 | 效果 |
|---|---|
| `日报` | 昨天的 AI 和科技新闻（也可以说「早报」） |
| `总结` | 把最近 30 条群聊用她的口吻概括成三句 |
| `查 某人` | 档案卡：发言数、最近活跃时间、我记得关于他的事 |
| `重置` | 清空当前会话的上下文 |
| `状态` | 查看当前配置（仅私聊） |

`查` 后面的名字支持模糊匹配——`查 蕾缪` 能匹配到「蕾缪·千早·爱弥斯」，旧昵称也能查到（因为 `person.aka` 留着）。

**必须带空格或冒号**。`查 朴俞喆` ✓，`查朴俞喆` ✗。不加这个限制的话，「查到问题了」会被当成人名去查。

### 档案卡长这样

```
某群友（1234567890）｜说过 12 句，最近 今天 19:23
· 爱刷炉石，输了就怪队友
· 2026-10-21 打本连第一阶段都没过
```

数据全来自 `person` + `memory` 两张表，**只显示这个人自己的记忆**，不会把群整体的梗混进来。

找不到人时她会说「「张三」……没印象，这人在群里说过话吗？」——不会瞎编。

### 加新指令

三处要同步改，少一处就留个坑：

1. `COMMANDS` 列表（决定菜单里显示什么）
2. `CMD_WORDS` 集合（决定这条消息会不会进聊天缓冲）
3. `handle()` 里的指令分支（实际执行）

第 2 步容易忘。忘了的后果是：指令会留在 `GROUP_RECENT` 里，重启后灌回背景，模型看到就容易被带偏——之前「@她 日报」被存进缓冲，导致后来问她一个陌生名字，她编了一段日报来应付。

## 语音

`@她 说 困死了` → 她用**达妮娅本人的音色**说一遍。本地跑 GPT-SoVITS，不联网、不花钱。

### 链路

```
文字 → bot → POST http://127.0.0.1:9880/tts（本地 GPT-SoVITS）
     → 32kHz wav（内存里的 bytes，不落盘）
     → record 段 base64:// → NapCat
     → addon 转 SILK → QQ
```

本地服务没起时**自动回退 edge-tts**，这时声音是微软的、不是她，但至少不会变哑巴。想彻底只在本地成功时才发，把 `voice.engine` 设成 `"local"`。

### 启动

双击 `start-voice.bat`，然后才是 `start-all.bat`。脚本干三件事：

- `cd` 到 `tts/GPT-SoVITS`
- 设 `FFMPEG_BIN` 指向 `tts/bin/ffmpeg.exe`
- 起 `api_v2.py`，监听 `127.0.0.1:9880`

模型加载约 60 秒，显存占 **1.7GB**（8GB 的 4070 很宽松）。这个窗口必须一直开着，关了语音就退化成 edge-tts。

下载走 `hf-mirror.com`，bucket 的路径**没有 `/main/`**：


### 权重格式要转一次

`G_164.pth` 是训练中间产物，只有 `model / iteration / optimizer / learning_rate`；推理要的是 `{"weight", "config", "info"}`。直接扔进去会报 `KeyError: 'config'`。

用训练时的 `logs/daniya/config.json` 当 hps 拼一下就行，产出 `SoVITS_weights_v2/daniya_e164.pth`（推理配置里指向这个）。

### 音色验证

`tts/batch_test.py` 生成三条不同情绪的句子，用 `librosa.pyin` 提基频做对比：

```
参考音频  9.7s  F0 中位 295 Hz  P10-P90 229-375
生成 01   7.9s  F0 中位 296 Hz
生成 02   8.3s  F0 中位 273 Hz
生成 03   9.4s  F0 中位 291 Hz
偏差 9 Hz —— 音高分布基本重合
```

基频只是可量化的那部分，最终还是要人耳判断语气像不像。用 GPT 权重是官方的，所以**音色像、韵律偏平**；想让语气也有她那种有气无力的感觉，得用这 9.5 分钟数据补训 GPT（8G 显存约 30 分钟）。

### 环境搭建踩的坑

这套依赖是 2024 年的，直接按 requirements 装会连环失败。按顺序记录：

| 坑 | 现象 | 解法 |
|---|---|---|
| **Python 版本** | `numba==0.56.4` 要 `llvmlite` 只支持 <3.11 | 用 **Python 3.10**，不能 3.11+ |
| **torch wheel** | cp310 和 cp311 是不同 wheel | 换版本后 2.4GB 要重下，选版本前先看 numba |
| **源码编译** | `jieba` / `distance` 只有 sdist，构建触发沙箱拦 `reg.exe` | 下 sdist 解压，纯 Python 直接放进 site-packages，再补 `dist-info` 让 pip 认 |
| **jieba_fast** | C 扩展，镜像上 404 | 写兼容层转发给 `jieba`（API 一致，慢一点不影响音质） |
| **transformers** | 没约束版本 → 装了 5.x → 提示 `PyTorch >= 2.6 is required`，直接禁用 torch | 钉 `transformers==4.44.2` |
| **LangSegment** | 0.2.0 的 `__init__.py` 导出 `setLangfilters`，但模块里只有 `setfilters`，包自身不一致 | 改 `__init__.py` 的导出列表 |
| **g2pw 模型** | 官方 paddlespeech 链接 404 | 从 `iqt-voice/G2PWModel` 下 7 个文件到 `GPT_SoVITS/text/G2PWModel/` |
| **gradio** | `tools/my_utils.py` 顶层 `import gradio`，但 `load_audio` 根本不用它 | 改成函数内惰性导入（否则为了个 UI 库还得装 gradio，还会把 numpy 拽到 2.x） |
| **ffmpeg** | 系统没有，`load_audio` 报 `WinError 2` | 装 `imageio-ffmpeg`，把自带的 exe 复制到 `tts/bin/`，用 `FFMPEG_BIN` 显式指定 |
| **ffmpeg 路径** | Git Bash 导出的 PATH 是 POSIX 格式，Windows 子进程不认 | 不能靠 PATH，必须传绝对路径 |

另外砍掉了 `funasr` / `Faster_Whisper` / `modelscope` / 韩粤语包——推理路径用不到，`oss2` 的编译还会卡住。

### 为什么不用自己转 SILK

NapCat 的 `native/ffmpeg/ffmpegAddon.win32.x64.node`（6.8MB）里带着完整 FFmpeg 和 SILK 编码器：

```
AVConvertToNTSilkTctWorker
SILK_V3
NTSilk
```

收到非 SILK 音频时它自己跑：

```js
语音文件${t}需要转换成silk
await Ni.convertToNTSilkTct(t, i)   // -c:a ntsilk_s16le -ar 24000 -ac 1
```

所以 Python 侧只要给出标准音频流。另一条路（Python 直接编 SILK）也试过：`pysilk` 在 PyPI 上是空包，`pilk` 要编译 C 源码、本机过不了。都不如让 NapCat 干活。

### 配置

```json
"voice": {
  "enable": true,
  "engine": "auto",
  "local_url": "http://127.0.0.1:9880/tts",
  "ref_audio": "../tts/ref/ref_010.wav",
  "ref_text": "每天都能睡个好觉，吃到美味的东西，还有就是……和朋友们在一起。",
  "speed": 1.0,
  "timeout": 120,
  "name": "zh-CN-XiaoyiNeural",
  "max_chars": 60
}
```

- `engine`：`auto` = 先本地、失败回退 edge-tts；`local` = 只用本地；`edge` = 只用微软
- `ref_audio` / `ref_text`：参考音频和它**逐字对应**的文本，GPT-SoVITS 靠这个定音色。换一句就得两个一起换
- `ref_audio` 支持相对路径（相对 `qqbot/`），换机器不用改绝对路径
- `speed` 大于 1 更快
- `max_chars` 硬截断：QQ 语音 60 秒上限，60 个中文字约 15 秒

`ref_text` 必须和音频内容一字不差，多一个标点都会让音色发飘。当前用的 `010.wav` 是「每天都能睡个好觉，吃到美味的东西，还有就是……和朋友们在一起。」——语气本身是慵懒的，正好合人设。

### 耗时

单句约 10~20 秒（8 秒音频），首句有预热会更久。所以 `tts_local` 跑在 `asyncio.to_thread` 里，不阻塞事件循环——否则这段时间整群消息都处理不了。

### ⚠️ QQ 端未验证

`200 OK` ✓、wav 8.04 秒 32kHz ✓、`record` 段正常发出 ✓、NapCat 转码链路已知 ✓——但**QQ 客户端能不能播，只有真发一次才知道**。

发出去如果是「语音加载失败」或者干脆不显示，看 `napcat/logs/*.log` 里有没有 `语音文件已就绪` 和 `时长` 两行：有「时长」说明转码成功、问题在 QQ 端（可能是风控拦非真人录音）；没有说明卡在转码。

## 联网搜索

用 **DeepSeek 自带的 Search API**，不需要接第三方：

```
POST https://api.deepseek.com/v1/tools/search   {"query": "..."}
```

同一个 key、同一个 base_url。返回结果带 `rerank_score`（0~3 的相关度）。

**计费**：每 1000 次成功请求 5 元（约 0.005 元/次），2026-11-01 起收费；搜索无结果或超时不计费。开关在 `config.json` 的 `search.enable`。

### 触发：先查，查不到再说不知道

最早做得很保守——只在明确问句时强制查。实测有两个漏网：

- **陈述句里抛生词**：「这波操作太滋溜咔了」没有任何疑问词，不触发
- **模型用反问掩饰不懂**：「滋溜咔是什么新型饮料吗」——既不查，也不说「不知道」，`不知道` 这类关键词一个都匹配不上

现在改成三层，从主动到兜底：

| 层 | 机制 |
|---|---|
| 1. prompt | 写死「顺序永远是：先查 → 查不到再说不知道」，并明确「哪怕你觉得自己好像知道，只要不是百分百确定，也先查」 |
| 2. 关键词硬引导 | 命中 `_ASK_RE` 且本地词典没命中 → 塞一条「必须先调 web_search 查，不许让对方自己去查」 |
| 3. **事后补救** | 回复里露出「不知道 / 听不懂 / …是什么…吗」这类信号，且这轮没调过搜索 → 自动追加一句「你刚才没查就说不知道，现在查」，**再跑一轮** |

第三层是关键，因为它不依赖模型自觉：**只要她露出「不懂」，就一定会被逼着查一次**。补搜之后如果确实搜不到，她会说「查了一圈，网上也没有」，而不是敷衍。

`_ASK_RE` 也从 11 个句式扩到 22 个，加了 `是不是`、`啥意思`、`哪来的`、`干嘛的`、`谁的`、`真的假的`、`靠不靠谱`。

实测：

| 输入 | 行为 |
|---|---|
| 「娅娅，这波操作太滋溜咔了」 | 直接调 `web_search`，回「查了一圈，网上只有猫舔冰淇淋的拟声词……这说法真没有」 |
| 「娅娅，卡提希娅是谁」 | 调搜索，答对 |
| 「娅娅我好困啊」 | **不搜**，正常闲聊 |
| 「娅娅今天几号」 | **不搜**，直接答「今天 22 号，周四」（时间在 system 里） |

4 条里 2 条搜索、2 条不搜——**该查的查，闲聊不浪费**。

自己的外貌、口味这类信息直接写在 `system_prompt` 里（「白发，发尾渐变成粉色再到浅紫，内层夹着蓝色，头顶一根呆毛」），所以问发色不会浪费一次搜索。

### 噪音怎么处理

搜索引擎**永远不会说"不知道"**——实测编造的词、甚至乱码，都照样返回 10 条结果。所以：

| 措施 | 说明 |
|---|---|
| 分数标注 | 每条结果带 `[2.1]` 这样的相关度，并在开头说明「低于 1.6 多半只是字面撞词」 |
| 自动收录阈值 | `rerank_score < 1.6` 的结果不会被写进词典 |
| 免责声明 | 结果前缀「来自网络搜索，不一定适用于本群」 |

实测分数分布：真实词条 1.77~2.09，编造词 1.52，无关乱码 0.18。**阈值只能挡住明显无关的，挡不住"字面相似但语义不同"**，所以把分数交给模型判断，而不是硬卡。

### 自动积累词典

每次搜到高相关度结果，会自动写进 `glossary_auto.json`：

```json
{
  "不烧心": "（网上搜的，未必准）“烧心”原指胃酸反流……近期 AI 短剧中“吃了不烧心”变成评价食材靠谱、不掺假"
}
```

下次群里再出现这个词，直接从词典命中，不再搜、不再花钱。跑几周会自动长成你群的语言环境。

- 上限 200 条，超出按新旧裁剪
- 条目带「（网上搜的，未必准）」前缀，和手写词条区分开
- **手写 `glossary.json` 优先**，同名词条以手写为准
- 觉得脏了就直接删掉整个文件

## 已知坑

### 改 bat 文件的两个死规矩

自己动手改 `.bat` 时，这两条不满足就会「双击没反应」或「一堆乱码报错」：

**① 必须是 CRLF 换行。** 很多编辑器（包括代码编辑工具）默认存成 LF。LF 的 bat 里 `if (...)` 多行块会被 cmd 解析乱，表现为脚本跑到一半就退出、或者把块里的某行当命令执行。检查：

```bash
python -c "raw=open('start-all.bat','rb').read(); print('CRLF', raw.count(b'\r\n'), 'bare LF', raw.count(b'\n')-raw.count(b'\r\n'))"
```

两个数字应该是 `CRLF=N 裸LF=0`。

**② 必须纯 ASCII。** 别在 bat 里写中文，注释也不行。`chcp 65001` 不解决这个问题——cmd 读取 UTF-8 多字节字符时会错位，实测把 `rem 快速登录：告诉 NapCat ...` 解析成了三行，其中 `NapCat` 被当命令执行，紧接着 `set "QQEXE=..."` 失效，`%QQEXE%` 变空，脚本报「QQ.exe not found at」后退出。

**③ 延时别用 `timeout`。** 两个坑：Git 装过「Unix 工具」的用户，PATH 里的 `timeout` 是 GNU 版，`/t` 参数不认；输出被重定向时 Windows `timeout.exe` 会报 `Input redirection is not supported` 直接退出。用绝对路径的 ping 最稳：

```bat
"%SystemRoot%\System32\ping.exe" -n 16 127.0.0.1 >nul
```

### 其他

- **别用主号**。协议端是模拟客户端登录，风控针对高频消息和新号。同一 QQ 号不能两处同时登录——用主号扫码会把你正在用的客户端踢下线。
- **NapCat 窗口必须一直开着**，关掉机器人就断了。不需要 BOT 时可以只关 Bot 窗口。
- 群聊一定保留 `at` 触发，否则每条都回，很快被踢。
- 上下文在内存里，进程重启清空；要持久化得自己接 sqlite。
- 同一个反向 WS 地址只能连一个实例，两个 Bot 抢同一端口会互相顶掉。
- NapCat 重启后二维码会变，旧 `qrcode.png` 立即失效。
